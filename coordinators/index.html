3 · Shared procedure every run

  1. Sweep abandoned trackers. Mark queued/running rows older than 12h as failed, preventing a crashed worker from permanently blocking the skip filter.
  2. Select today's bucket for the coordinator's pattern.
  3. Apply skip filters (per-pattern — see cards above).
  4. Enqueue to the appropriate SQS queue with submitted_by = 'coordinator'.
  5. Refresh forecast_priority materialized view so EmpowerFresh picks up new work immediately.

6 · Out-of-sequence training & forecasting

When the coordinators aren't the only ones enqueueing work

Data-driven training and forecasting fires whenever a file import or user action changes the shape of the historical data or the forecast horizon. These runs are enqueued out-of-sequence, independent of the EventBridge cron. The chain is always trigger → job type → downstream effect, with a careful interaction against the normal coordinator sequence.

Trigger (data change)
  • Product merge — reshapes historical sales → train
  • New product activated — introduces new series → train
  • New price file imported — changes forecast feature → forecast
  • Horizon / series change via user action → forecast
→
Out-of-sequence job
  • Training refresh enqueued immediately
  • Forecast refresh enqueued immediately
  • Runs through the same SQS → worker path as coordinator jobs (same ai_job_tracker, same ML worker)
→
Downstream
  • Training complete → auto-enqueues a forecast using the new model
  • Forecast complete → writes ai_forecast_performance row with fresh forecast_created_at
  • Fresh forecast_created_at is the hook that lets coordinators skip the next scheduled run (next section)

Honors 48h rule Forecast coordinators

config_forecast and dense_forecast will skip today's bucket for a (customer, store, product) if ai_forecast_performance shows a row for the latest model with forecast_created_at > NOW() - 48h.

Effect: if an out-of-sequence forecast lands within 48h of the scheduled slot, it replaces that slot and the coordinator pass is a no-op for that series. The forecast then waits a full cycle until the next bucket day — it could therefore age to 9 days at most (7-day cycle + up to 2 days of replacement window). Rare, but possible.

Ignores 48h rule Training + stats coordinators

config_train, dense_train, and stats always refresh on schedule regardless of any out-of-sequence run that happened in the last 48 hours.

Why: stats refreshes across products — it can't skip one individual job without unbalancing the bin-packed batch. train has a 28-day window which is too long to ever want to skip a scheduled slot. The only reason a training or stats job is not enqueued at its normal run time is that the ai_job_tracker already has a queued or running row for it.
